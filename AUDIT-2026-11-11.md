# Audit record, 11 November 2026

An independent read-only audit of the README, the report PDF and the notebook (`code/Lekki_Hydro_Study.ipynb`) was run on commit 62a0a9a. The notebook, the PDF and the figures were not changed. The commits that followed correct the README only.

## Findings

| Finding | Evidence | Status |
| :--- | :--- | :--- |
| The README and PDF misreport the notebook result | The notebook prints a whole-basin index change of 5.16% and 18.14% for the Lekki urban core. The README and PDF said an 18.1% whole-basin reduction and over 45% in the urban core. The urban-core figure was relabelled as basin-wide, and 45% appears in no output | README corrected; the PDF is not |
| The recharge index rests on fixed assumptions | The weights 0.30, 0.25, 0.20, 0.15 and 0.10 and the recharge coefficient 0.35 are not calibrated, sourced or tested for sensitivity. Recharge is `rain * 0.35 * ARPI` | README states this |
| The MODFLOW model is not usable | The notebook calls only `write_simulation()` and never runs the model, so there are no head or budget outputs. Recharge in mm per year goes into a model set in metres and days (a factor of about 365,000 too large). There is no constant-head or general-head boundary and no inactive-cell mask, hydraulic conductivity is never set, and the top and bottom elevations are uniform. The README also says recharge was scaled by specific yield, which appears nowhere in the code | README states this |
| The 1995 baseline is not 1995 | The baseline is a 1986 to 1996 Landsat-5 median, so "30-year" and "1995 to 2024" overstate the interval | README reworded |
| The sensor harmonization is circular | The shifts are chosen so the eastern 30% of the raster columns, a column cut and not a mapped rural area, shows no change. That zone is part of the area being assessed | README states this |
| Rainfall is the same in both epochs | The 2019 to 2023 CHIRPS mean is used for both, so rainfall cannot contribute to change, and the 0.05 degree product is resampled to 30 m | Open |
| "TWI" is not a topographic wetness index | `catch_area` is a shifted, clipped negative Laplacian, not upslope contributing area | Open |
| The percolation routing has no physical basis | Dijkstra runs over a function of the surface index. Groundwater flow follows head gradients and conductivity, the start and end points are raster fractions, and route length ignores diagonal steps | README reworded |
| No validation | Nothing is compared with impervious-surface reference data, piezometric or recharge records, or an accuracy assessment of the built-up index | Open |
| The notebook was run out of order | Execution counts run 3, 4, 11, 15, 16, 17, 26, 31 and 32, and the Earth Engine export it reads is not stored | Open |
| One report reference may be mis-titled | Reference 1 (Bakker et al., 2016) is probably "Scripting MODFLOW model development using Python and FloPy". Not checked online. The report also cites MERIT Hydro while the code uses Copernicus GLO-30 | Open |

## Corrected in the commits that follow 62a0a9a

A status notice, the map caption and the two headline findings, the pipeline and index descriptions, how recharge is computed, and the percolation wording.

## Open

- Making the model usable needs boundary conditions, a conductivity field, unit conversion and a run with heads and a water budget, plus observations to compare with. None is available here.
- A weight and coefficient sensitivity analysis would be needed before the index can be called recharge potential.
- The PDF repeats the misreported figures and has not been changed.
